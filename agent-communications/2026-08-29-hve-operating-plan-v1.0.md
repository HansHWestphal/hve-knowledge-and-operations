# Human Value Exchange Operating Plan

**Version:** 1.0  
**Status:** Approved operating baseline  
**Effective:** 2026-08-29  
**Review cadence:** Weekly through the Monday 00:07 HVE mission-review workflow

## Purpose

This is HVE's small, explicit operating plan. It translates the mission into
current ownership, priorities, and execution rhythm without duplicating the
mission brief, agent memories, runtime configuration, or decision history.

The latest approved weekly decision ledger governs changes to this plan and
active policy.

## Mission and strategic posture

Human Value Exchange is a pre-launch, human-guided and agent-accelerated
organization dedicated to strengthening human sovereignty through the Human
Life Operating System and Five Wealth framework.

The 2026 operating sequence is:

1. Validate the Five Wealth Framework.
2. Use Time Wealth as the first pilot because it provides the strongest learning
   base.
3. Advance the remaining pillars through evidence-led experiments and offer
   development.
4. Treat launch timing, pricing, channel ownership, and public messaging as
   active policy only when approved through the dated-policy gate.

## Authority and ownership

- **Hans Westphal — CEO:** final authority over purpose, values, priorities,
  commitments, ownership, and decisions.
- **hanshermesagent — Chief of Staff:** coordinates CEO-led work, maintains
  continuity, surfaces conflicts, prepares decisions, verifies outcomes, and
  routes work to the correct owner.
- **Wolfgang Westphal — HVE intern:** develops the new Instagram channel,
  creates nutrition plans within the Physical Wealth pillar, and supports Hans
  with Time Wealth pillar activities.
- **Other agents and specialists:** operate only within their approved profile
  lanes and the current decision ledger.

No agent may make an external, financial, legal, contractual, privacy-sensitive,
or irreversible commitment without the required approval.

## Current priorities

1. Validate and improve the Time Wealth pilot.
2. Define evidence-based offer paths across the Five Wealth pillars.
3. Build repeatable delivery workflows and measurable client outcomes.
4. Develop HVE content and channels that convert sovereignty into practical
   decisions, observable behavior, or next actions.
5. Improve agent coordination, provenance, handoffs, and weekly accountability.

Priorities may change only through the approved weekly decision ledger or an
explicit CEO decision.

## Weekly operating rhythm

- Collect evidence from approved HVE sources for the completed Monday-Sunday period.
- Run the Monday 00:07 HVE mission-review workflow.
- Separate verified facts, attributed claims, inferences, risks, recommendations,
  and unknowns.
- Record approved decisions, owners, effective dates, review dates, and
  superseded decisions in the weekly decision ledger.
- Rank no more than seven next actions, each with an owner and observable
  completion measure.
- Review unresolved conflicts and decisions requiring Hans's judgment.

## Dated-policy gate

A strategic policy is active only when it has:

`owner + approval status + effective date + review date`

This gate applies to pricing, discounts, launch dates, channel ownership, pilot
sequencing, public messaging, partnerships, and other material commitments.
Undated memories, chat statements, external claims, and informal notes are not
active policy.

## Content and delivery standard

HVE work must preserve human purpose, judgment, values, decisions, data
ownership, and direction. Agents accelerate research, analysis, coordination,
drafting, and execution support.

Do not ship hype, doctrine, unsupported authority claims, generic motivation,
invented commitments, or unverified outcomes. Prefer measurable, reversible,
privacy-preserving, and explainable work.

## Source-of-truth and GitHub workflow

Use this order for operating decisions:

1. Hans's explicit current decision.
2. The latest approved weekly decision ledger.
3. This operating plan.
4. `instructions.md` for broad mission and framework context.
5. `MEMORY.md`, `USER.md`, chat, and external material as supporting context.

If sources conflict, preserve provenance and escalate rather than improvise.

GitHub is the system of record for approved durable HVE artifacts and decisions:

`Draft → approval → verification → commit → push → authoritative record`

Do not commit or push drafts, unapproved policy, transient notes, runtime state,
credentials, or sensitive data. A local file or chat message is not authoritative
until the approved artifact has been successfully committed and pushed.
